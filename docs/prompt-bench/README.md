# Prompt Bench

同一のシステムプロンプト・ユーザープロンプト・パラメータを固定してN回繰り返し実行し、出力のばらつきを検証するツールです。ビルド不要の単一HTML(`index.html`)で、GitHub Pages上でそのまま動作します。サーバーは使わず、ブラウザから直接OpenAI互換APIを叩きます。

## 使い方

### 1. 接続設定
- 「プロバイダプリセット」でOpenRouter(既定) / Groq / Together AI / カスタムを選択すると、Base URLと候補モデルが自動入力されます。「OpenAI互換API」はリクエスト形式が同じという意味で、APIキーはプロバイダ間で共通ではないため、各プロバイダのサイトで個別に発行してください
- 「API キー」は必須項目です。入力するまで「モデル一覧を取得」「実行」ボタンは押せません。ブラウザのJS変数上にのみ保持され、localStorage等への保存は行いません
- 「モデル一覧を取得」を押すと、そのアカウントが実際に使えるモデルIDを取得できます

### 2. プロンプト
- システムプロンプト(任意)とユーザープロンプトを入力します

### 3. パラメータ
- **temperature**(既定値`0`=決定論的)が主に調整するパラメータで、それ以外は基本的に触らなくてよい設計です
- 繰り返し回数(1〜30)・同時実行数(1〜10、レート制限を考慮し既定は1)
- **ストリーミングで受信する**: 有効にすると生成中の出力をリアルタイムに表示します。出力が大きい場合、非ストリーミングだと1回の巨大なレスポンスを待つ間にプロバイダ/経路側のタイムアウトで途中までしか受信できないことがありますが、ストリーミングはデータが継続的に流れるためこの問題を避けやすくなります
- **+ 詳細パラメータ**(top_p / max_tokens / reasoning_effort / Structured Output): それぞれチェックを入れたときだけリクエストに含まれます。未指定のままならモデル/プロバイダ側の既定値が使われます
  - `max_tokens`を未指定のままにすると、プロバイダによっては1リクエストあたりのレート制限判定(例: Groqの分単位トークン上限)にモデルの既定最大出力が使われ、常に「リクエストが大きすぎる」扱いになることがあります。無料枠などタイトなレート制限に当たる場合は、小さめの値を明示的に指定してみてください
  - `reasoning_effort`(low/medium/high): 推論(reasoning)モデル(gpt-oss系など)の思考量を指定します
  - Structured Output: JSONモード(`json_object`)またはJSON Schema(`json_schema`・厳密)を指定できます。スキーマ入力欄には例とツールチップがあります

### 4. 評価オプション(任意)
- **LLM-as-Judge**: 採点基準(rubric)を書くと、各出力を1〜10点で自動採点します。本文の実行が全件終わってから採点フェーズに入るため、本文の結果は採点を待たずに順次表示されます
- **Embedding類似度**: 出力同士のコサイン類似度でばらつきを定量化します。Groqはembeddingsエンドポイントを提供していないため、別途OpenAI等のBase URL・APIキー・モデルを指定してください
- **傾向分析**: N個の出力すべてを1回のLLM呼び出しでまとめて読ませ、「共通する内容」「分岐している内容とその内訳」「分岐が表現の違いか、結論が変わる実質的な違いか」を文章で要約させます。テスターが再現性の問題を判断する補助として使えます
- **出力のJSON形式を検証する**: LLM呼び出しなしで、各出力をその場でパースし、「途中で切れていないか」「同じキーが複数出現していないか」(JSON.parseは重複キーを無言で上書きするため専用パーサーで検出)をチェックします

### 5. 実行・結果確認
- 「実行」で開始、「停止」でいつでも中断できます(レート制限で待機中でも即座に中断されます)
- 429(レート制限)は自動的にリトライされ、諦めずに待ち続けます(Stopボタンでのみキャンセル可能)。429と混同しやすい413(Request too large)は待っても解決しないエラーで、`max_tokens`を明示的に小さくするなどリクエスト自体を縮める必要があります
- 実行結果は完了したものから順次カードに表示されます(全件・Judge・Embedding・傾向分析がすべて終わるまで待つ必要はありません)
- 各実行カードのバッジ(ⓘアイコンで説明表示): 合計レイテンシ / (ストリーミング時のみ)初回トークンまでの時間 / prompt・completion・totalトークン数 / プロンプトキャッシュヒット数(対応プロバイダのみ) / finish_reason / 残TPM(対応プロバイダのみ) / JSON検証結果
- サマリーには成功数・平均レイテンシ・平均トークン数・Judge平均スコア・Embedding平均類似度・JSON妥当率と、推移グラフ・類似度ヒートマップが表示されます
- 「結果をコピー」でMarkdownレポートをクリップボードにコピー、「JSONエクスポート」で生データをファイル保存できます

## 既知の制約
- ブラウザから直接プロバイダのAPIへリクエストするため、Origin制限のあるプロバイダでは失敗する場合があります(その場合はプロキシ経由での呼び出しが必要です)
- APIキーはページを閉じると消去されます
- このツール自体はリクエストにタイムアウトを設けていません。長時間かかったり途中で切れたりする場合は、プロバイダ/経路側の制限が原因である可能性が高く、ストリーミングを有効にすると回避しやすくなります
- プロンプトキャッシュ(同一プレフィックスの再利用)はGroq等のプロバイダ側で自動的に行われるものです。本ツールから明示的に有効化する設定はありません(ヒットした場合はキャッシュ:Nバッジで確認できます)
